# Валькирии — PR-ньюсрум

> Мультиагентный PR-конвейер с дашбордом: находит инфоповоды, переупаковывает материал под несколько СМИ с проверкой уникальности и оценивает медиаэффективность публикаций в PR Points.

Учебно-портфолиный проект: три Claude Code субагента (Хильда, Сага, Фрейя) и статический дашборд-витрина над результатами их работы.

**[→ Смотреть живой дашборд](https://dashboard-eight-silk-grapxsh6eu.vercel.app)**

---

## О проекте

**Проблема.** PR-отдел ведёт несколько процессов вручную и в разных местах: ловит инфоповоды для оперативной реакции, переупаковывает один материал под разные издания с проверкой уникальности и оценивает медиаэффективность вышедших публикаций. Всё живёт в файлах, папках и почте — нет единой картины, приоритеты теряются, эффект сложно показать руководству.

**Решение.** Сквозной конвейер из трёх агентов и один дашборд, где видно весь процесс: что горит, что готово к питчу и что в итоге сработало.

**Пользователь.** PR-специалист и небольшая PR-команда.

---

## Что делает

- **Хильда** — newsjacking-скаут. Сканирует медиаполе, квалифицирует поводы по чек-листу из 6 критериев и присваивает приоритет (срочно / важно), готовит брифы.
- **Сага** — агент-адаптер. Берёт бриф и делает 4 стилистически разных версии под СМИ (Forbes Russia, РБК Компании, Инк, Setters Media), проверяя уникальность каждой через API text.ru.
- **Фрейя** — пайплайн оценки. Считает PR Points (методика Skyeng) по публикациям и строит рейтинг бренда против конкурентов.
- **Дашборд** — витрина, которая показывает результаты трёх агентов в одном окне.

---

## Архитектура

```
Хильда (newsjacking)  →  Сага (адаптация)  →  [публикация]  →  Фрейя (PR Points)
   находит и                4 версии под СМИ                     оценивает выходы
   приоритизирует           + уникальность                       и строит рейтинг
        │                         │                                    │
        └──────────────── всё стекается в дашборд ───────────────────┘
```

Субагенты Claude Code не вызывают друг друга — последовательность задаёт главная сессия по `CLAUDE.md`. Дашборд читает готовые результаты прогонов, а не запускает агентов в браузере.

---

## Стек

- **Агенты:** Claude Code субагенты (модели Sonnet и Haiku), Anthropic API.
- **Проверка уникальности:** API text.ru.
- **MCP:** веб-поиск (brave-search / tavily), fetch, Google Drive, Memory, Gmail.
- **Дашборд:** статический HTML/CSS/JS без сборки (веб-шрифты Google Fonts).
- **Деплой:** Vercel / GitHub Pages (статика).

## Установка и запуск

### Требования
- Claude Code
- Python 3 (для расчёта PR Points)
- Ключи: Anthropic API, text.ru (см. ниже)

### 1. Секреты

Скопируй шаблон и заполни своими значениями **локально** (этот файл не попадает в репозиторий):

```bash
cp .env.example .env
```

Содержимое `.env.example`:

```
ANTHROPIC_API_KEY=your_key_here
TEXTRU_API_KEY=your_key_here
GDRIVE_OUTPUT_FOLDER_ID=your_folder_id_here
OPERATOR_EMAIL=operator@example.com
BRAVE_API_KEY=your_key_here
```

### 2. Запуск агентов

```bash
claude          # в корне проекта
/agents         # проверить, что субагенты подхватились
```

Команды главной сессии:

```
Хильда, найди поводы по теме X      # брифы с приоритетом → output/briefs/
Сага, адаптируй бриф <id>           # 4 версии под СМИ + summary.json
Фрейя, запусти пайплайн             # рейтинг PR Points → output/pr-report.md
```

### 3. Запуск дашборда

Открой `dashboard/index.html` в браузере — он сразу работает на демо-данных, сборка не нужна. Чтобы перейти на реальные прогоны, замени объект `DATA` в начале скрипта на чтение файлов из `output/`.

---

## Пользовательский сценарий

1. PR-специалист просит Хильду найти поводы по своим темам. Хильда возвращает брифы, помеченные «срочно сегодня» или «важно на неделе».
2. По выбранному брифу запускается Сага: получаются 4 готовых к питчу версии под разные СМИ, каждая с подтверждённым процентом уникальности.
3. После публикаций Фрейя оценивает выходы в PR Points и строит рейтинг бренда против конкурентов.
4. Всё это специалист видит на одном дашборде: ленту поводов с приоритетом, карточки версий с уникальностью и рейтинг эффективности.

## Безопасность данных

В репозитории не должно быть ничего чувствительного. Перед публикацией проверь:

- Реальные ключи, токены, личные адреса и абсолютные пути **не зашиты** в код и промпты — только переменные окружения и плейсхолдеры.
- Адрес рассылки берётся из `OPERATOR_EMAIL`, а не задан в тексте.
- Полные тексты чужих статей (РБК, Forbes и т.п.) **не коммитятся** — в `data/articles/` только короткие примеры или выдержки (авторские права).
- В консоли Anthropic выставлен лимит расходов.

Рекомендуемый `.gitignore`:

```
.env
.env.*
!.env.example
secrets/
credentials/
*.key
*.pem
**/memory/*.json
output/
data/articles/*
!data/articles/example_*.txt
node_modules/
.DS_Store
```

Если секрет всё же попал в историю коммитов — почисти историю (`git filter-repo`) и **перевыпусти** этот ключ.

### Тексты публикаций: локально и в репозитории

Чтобы не нарушать авторские права и при этом сохранить точность анализа, тексты разнесены на два слоя:

- **Полные тексты публикаций — только локально.** Они лежат в `data/articles/` под именами `full_*.txt` и исключены из репозитория через `.gitignore`. Именно на полных текстах Фрейя делает точный анализ (по 3–5 предложениям формат публикации не определить надёжно), поэтому реальный прогон выполняется локально.
- **В репозиторий идут безопасные версии:** файлы-выдержки `example_*.txt` (шапка «Источник / дата / ссылка / Кампания» + дословная выдержка 3–5 предложений + 1–2 предложения пересказа своими словами + ссылка на оригинал) и итоговый отчёт `output/pr-report.md`. Отчёт публиковать можно — это аналитический продукт (оценки, рейтинг, короткие пересказы), а не перепечатка чужих статей.

Итог: полные статьи → локальный прогон → точный отчёт; в репозитории — выдержки со ссылками и сам отчёт. Пресс-релизы компании (исходный материал для Саги) можно класть как пример — они создаются для распространения; убедись, что версия опубликованная и без внутренних данных.

## Ограничения (честные границы)

- PR Points — порядковая шкала (больше/меньше, динамика), а не точное измерение.
- Формула упрощена: критерии «инициатор» и «новизна издания» из полной методики Skyeng не учитываются (требуют данных из CRM).
- Сбор статей для Фрейи — ручной (автосбор через веб-поиск даёт галлюцинации и пропуски, для PR-отчёта это недопустимый риск).
- Дашборд по умолчанию работает на демо-данных; чтение реальных файлов прогонов подключается отдельно.
